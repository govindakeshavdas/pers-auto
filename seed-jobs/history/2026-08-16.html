1. AgentMail — 🔴 — Email inbox API built for AI agents
agentmail.to · San Francisco · founded 2025 · seed (~$6M) · ~8 people · YC S25
agentmail.to · YC profile
What they do
  • API that gives AI agents their own email inboxes with threading, parsing, labeling, and replying.
  • A single API call creates an inbox. No OAuth flows, no manual setup, no human in the loop.
  • Real-time webhooks and websockets. Semantic search across inboxes.
  • Shared domain with reputation management built in.
The problem they solve
  • Give the agent your personal email and lose control of your inbox.
  • Buy a domain per agent and deal with DNS, DKIM, SPF, deliverability.
  • Example: a procurement agent needs to email vendors, receive quotes, follow threads — without hijacking a human inbox.
Money
  • Usage-based pricing that works for agents.
  • 500+ B2B customers, hundreds of thousands of agent users.
  • $6M seed led by General Catalyst, with YC, Paul Graham, Dharmesh Shah angels.
Why now
  • AI agents are becoming autonomous actors that need persistent digital identities.
  • AgentMail's larger purpose is to serve as an identity layer for AI agents.
Bootstrap fit
  • Grader: Objective — email delivery, threading, parsing are mechanical.
  • LLM deleted: Email infra remains. DKIM, SPF, domain rep, API — no AI needed.
  • Accumulates: Domain reputation takes months. But SendGrid/Mailgun add agent inboxes as a feature. 🔴
  • Week one: API key → inbox → send/receive. Works immediately.
  • Buyer: Developers building agents. Reachable. Will pay usage-based.
Verdict: 🔴 — Gate 3. Single-function utility that existing email infra providers (SendGrid, Mailgun, Postmark) absorb as a feature line. Domain reputation accumulates but isn't unique to the product. Crowding
  • Primitive (YC P26) is building similar email infrastructure for agents.
  • SendGrid, Mailgun, Postmark all have the infra — just haven't shipped agent-specific APIs yet.
2. Indexable — 🔴 — Sandbox infrastructure for AI agents
ix.dev · San Francisco · founded 2026 · pre-seed (YC P26) · ~3 people · YC P26
ix.dev · YC profile
What they do
  • Sandbox infrastructure for AI agents — fork and snapshot environments in 26 milliseconds.
  • Full state snapshots include process memory and databases, not just filesystem.
  • Runs a custom Linux 6.19 kernel.
  • Full-environment forks and snapshots across files, processes, memory, and databases.
The problem they solve
  • AI agents executing code need isolated environments they can fork, mutate, and roll back.
  • Container-based approaches can't snapshot process memory and DB state together.
Money
  • Usage-based compute pricing (standard for sandbox infra).
  • Revenue/pricing not publicly disclosed.
Why now
  • AI-generated code volumes surge — Cursor alone produces nearly a billion lines of accepted code daily.
Bootstrap fit
  • Grader: Objective — latency, snapshot fidelity, isolation are measurable.
  • LLM deleted: Pure systems infra remains. No AI dependency.
  • Accumulates: Kernel-level engineering is hard. But crowded field absorbs it. 🔴
  • Week one: API → spin up sandboxes. Works immediately.
  • Buyer: AI teams needing code execution. Reachable via dev marketing.
Verdict: 🔴 — Gate 3. Extremely crowded infra race. Direct competitors include E2B (well-funded), Blaxel (YC S25), Playgent (YC S25), Hopx, Modal. Cloud providers are building sandbox primitives natively. A solo founder can't out-engineer these teams on kernel-level VM infrastructure. Crowding
  • E2B, Modal, Daytona, plus Northflank, Bunnyshell, Cloudflare, Vercel, Fly.io all ship sandbox products.
  • Kubernetes SIG-Apps is standardizing a Sandbox primitive.
