1. Temper 🟡 — AI agents that build, deploy, and fix supply-chain integrations
Supply-chain integration · ontemper.com · San Francisco · ~2024 · Seed (~$8M) · ~8 people
What they do
  • Agentic integration platform: AI agents handle the full lifecycle of supply-chain data integrations.
  • Automates EDI transactions (850s, 856s, 810s) without manual mapping.
  • When something breaks, the agents fix it.
  • Connects ERP, TMS, WMS, and carrier systems with AI-generated code.
The problem they solve
  • Every time two companies exchange data, someone builds a custom integration by hand. Manual, every time.
  • Example: a 3PL needs to connect a new shipper's TMS to its WMS. Old way: 3–6 months of analysts + engineers. Temper: hours.
  • Founders built a logistics startup from pre-seed to 400+ people. Dealt with broken integrations for years.
Money
  • Paying enterprise customers. More demand than they can keep up with. Seed-funded with over $8M raised.
  • Revenue model: platform fees per integration or per connection.
Why now
  • LLMs can now generate, test, and debug integration code reliably enough to automate what was pure services work.
  • Turns months of manual engineering into hours.
Bootstrap fit
Objective: Integration either works or breaks — round-trip testable. ✅
LLM deleted: Code-gen engine + integration test harness remain. ✅
Accumulates: Library of working integration templates and EDI maps. ✅
Week one: Customer names two systems; agent writes and deploys the connection. ✅
Buyer: IT/ops leads at 3PLs and shippers. Pay to avoid months of services work. ✅
Verdict: 🟡 — Passes all gates technically. But $8M raised, ~8 people, deep supply-chain operator founders, and already more demand than they can fill. Competing here means catching up to a well-resourced team with domain credibility and enterprise customers. The template library accumulates, but so does theirs — faster.
Crowding
  • Legacy EDI vendors (SPS Commerce, Cleo) are large but not AI-native.
  • Pandium, Workato, Celigo do iPaaS but are horizontal, not supply-chain specific.
  • The vertical + AI-agent combo is still sparse.
2. ZUUZ 🟡 — AI layer that captures sales pipeline from email into CRM
Sales pipeline capture · zuuz.ai · Sunnyvale, CA · ~2025 · Pre-seed · ~1–5 people
What they do
  • Reads every email in a sales inbox, qualifies the lead, drafts the reply, and tracks the deal — automatically.
  • Matches customer requirements against the seller's catalog and prepares quotes.
  • Syncs captured pipeline back to CRM (HubSpot, etc.).
The problem they solve
  • RFP responses, renewal negotiations, and deal registrations move through email, not CRM. Pipeline visibility lives in reps' memory.
  • Within 30 days at RA Technologies, ZUUZ surfaced $120K in active pipeline that had never been recorded in CRM.
Money
  • RA Technologies is live at $50K ARR with 50+ active users.
  • In production at RA Technologies, Cloud Box, Nesto, and WIG.
  • Tiered SaaS pricing: 1 mailbox (solo) through unlimited (enterprise).
Why now
  • LLMs can now reliably classify inbound emails by intent (RFP, renewal, cold inquiry) and extract deal fields.
  • SMB sales teams still use email as the real system of record.
Bootstrap fit
Objective: Email → deal record is checkable: does it match what's in the email? ✅
LLM deleted: Email parsing rules + CRM sync pipeline remain. Thin. ⚠️
Accumulates: Classification accuracy improves with labeled emails. Modest moat.
Week one: Connect mailbox, pipeline appears within hours. ✅
Buyer: SMB sales managers (1–10 reps). Real budget but small ACV.
Verdict: 🟡 — Functional day one, buyer is reachable, output is checkable. But the CRM-sync-from-email space is crowded (Clari, Troops, Regie, Attio auto-capture, HubSpot AI). The LLM layer is thin — an intern-scale integration over model calls. What accumulates is the catalog-matching logic for niche industries (distribution, B2B wholesale), but a platform can absorb the core feature.
Crowding
  • Clarify, Attio, Streak — CRMs with auto-capture already built in.
  • Clari, Gong — pipeline intelligence tools for mid-market+.
  • ZUUZ's niche: SMB distribution/wholesale where the "catalog match" adds value beyond generic CRM capture.
3. Spur 🔴 — AI QA agent that tests websites via natural language (YC S24 — included for reference)
QA testing · spurtest.com · New York · 2024 · Seed (~$4.5M) · ~8 people
What they do
  • AI QA agent. Users type natural-language test instructions; Spur launches web agents that mimic real users.
  • AI-driven browser agents emulate real user interactions without CSS selectors or code access.
  • Teams like Alo and HelloFresh cut regression testing time by 95%.
The problem they solve
  • Testing is time-consuming and painful. Tests break because UI is constantly changing.
  • Example: e-commerce team deploys a checkout change. Old way: re-write Selenium scripts. Spur: re-run same natural-language instruction.
Money
  • Raised $4.5M seed led by First Round Capital.
  • Founded by Yale alums, ex-Figma & DeepMind. Backed by First Round, Neo, Pear VC, Conviction.
  • SaaS pricing; customers include NextDoor, LivingSpaces, Wander.
Why now
  • Multimodal LLMs can now navigate web UIs visually, making selector-free testing possible.
Bootstrap fit
Objective: Test pass/fail is checkable — page state matches expected state. ✅
LLM deleted: A browser automation harness. Thin — the LLM is the product.
Accumulates: Nothing durable. Better prompts, better browser-use agents — but model providers ship these natively (Anthropic computer use, OpenAI Operator). 🔴
Week one: Works immediately — no data needed. ✅
Buyer: Eng/QA leads. Real budget. ✅
Verdict: 🔴 — Fails gate 3 (durability). Browser-use agents are a platform feature, not a product. Anthropic, Google, and OpenAI are all shipping native browser interaction. The "natural language → browser action" layer commoditizes within 18 months. Also YC S24 with First Round backing — wrong competitive target.
Crowding
  • QA Wolf, Cypress, Playwright, Rainforest QA — established testing tools.
  • Anthropic computer-use, OpenAI Operator — platform-level browser agents.
  • Numerous YC/seed-stage AI testing startups (Momentic, Carbonate, etc.).

5. Haladir 🔴 — Formal solvers + LLMs for logistics optimization (YC W26 — included for reference)
Logistics optimization · YC page · San Francisco · 2025 · Seed (~$4.3M) · 4 people
What they do
  • Combines formal solvers with LLMs to give models a fundamental understanding of constraints. For logistics: routing, scheduling, resource allocation.
  • Builds at model training layer (solver-based RL environments for frontier labs) and application layer (model harnesses for constrained workflows).
  • Sits on top of WMS, TMS, OMS, unifies data into one operational graph.
The problem they solve
  • Top models often fail to understand constraints in difficult scenarios. Optimizing across systems with millions of interdependent variables under hard constraints remains beyond current models.
  • ConstraintBench: frontier models score under 65% feasibility on standard OR tasks.
Money
  • Raised seed round, total funding $4.3M. Led by BoxGroup and Susa Ventures.
  • Two revenue lines: selling RL training environments to AI labs + selling optimization layer to logistics firms.
Why now
  • RLVR (RL with verifiable rewards) changed post-training. Formal verification provides checkable ground-truth for RL.
  • LLMs can now orchestrate solver calls, but can't replace them for constraint satisfaction.
Bootstrap fit
Objective: Solver output is verifiably optimal/feasible — checkable. ✅
LLM deleted: Formal solvers, RL environments, constraint specs remain. Real depth. ✅
Accumulates: ConstraintBench datasets, solver harnesses, customer constraint graphs. ✅
Week one: Needs customer's WMS/TMS/OMS data and operational constraints. Cold start. 🔴
Buyer: VP Ops at logistics companies. Procurement-gated, long sales cycle. 🔴
Verdict: 🔴 — Real technical depth (passes gates 1–3), but fails gate 4 (needs live operational data from customer systems) and gate 5 (enterprise logistics buyers are relationship-gated, long procurement). Also YC W26 with $4.3M — not a bootstrap target.
Crowding
  • Palantir Foundry, Google OR-Tools, Gurobi — incumbent optimization tools.
  • FourKites, project44 — logistics visibility but not optimization.
  • Few startups combining formal methods + LLMs specifically.
6. sieve 🔴 — AI + human review for hedge fund data cleaning (YC P2025 — included for lack of non-YC equivalent)
Financial data cleaning · usesieve.com · New York · 2025 · Pre-seed (YC) · 2 people
What they do
  • Solves data cleaning for hedge funds: API that integrates into existing pipeline, returns clean, high-quality data.
  • AI finds source documents and extracts data. Expert reviewers verify each data point. Achieves accuracy AI-only approaches can't.
  • Offers direct API access and Excel integration.
The problem they solve
  • Most sophisticated hedge funds pay over-qualified data engineers to spend hours daily on data cleaning. Even earnings dates are a known hard problem in finance.
  • Example: fund needs clean earnings dates across 5,000 tickers from SEC filings. Old way: analyst combs PDFs. sieve: API call returns verified data.
Money
  • Founded in 2025 by Nicole Lu, 2 employees based in New York.
  • Founder previously at Citadel (quant research, trading, data science) and McKinsey.
  • Usage-based pricing per data point cleaned.
Why now
  • LLMs can now extract structured data from messy financial documents (PDFs, foreign filings).
  • Human-in-the-loop hybrid model covers the accuracy gap that pure AI can't close.
Bootstrap fit
Objective: Data point matches source document — checkable. ✅
LLM deleted: Expert reviewer network and financial domain knowledge remain. 🔴
Accumulates: Verified data corpus and extraction rules — real, but domain-owned.
Week one: Works — customer sends data request via API. ✅
Buyer: Hedge fund data teams. Relationship-gated, high-trust. 🔴
Verdict: 🔴 — Fails gate 2. The value is financial domain expertise (knowing what "clean" means for earnings dates, corporate actions, etc.) plus human reviewer network. An ex-Citadel founder hiring one engineer beats a generalist here — and that's exactly their founding story. Strong traction signal, bad bootstrap target. Also gate 5: hedge fund buyers are relationship-gated.
Crowding
  • S&P, Bloomberg, FactSet — incumbents with massive data teams.
  • Addepar, Novus — portfolio analytics but not raw data cleaning.
  • Small niche — few startups attacking the data-cleaning-as-API angle specifically.
