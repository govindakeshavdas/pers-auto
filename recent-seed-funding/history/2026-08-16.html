1. Intelligence 🔴 — Crowdsourced AI design benchmarking

AI evaluation · San Francisco · intelligence.ai · $7.9M seed (Aug 2026)

What they do

  • Users submit prompts, get AI-generated designs, vote A vs. B on outputs.
  • Aggregated human-preference rankings sold to frontier labs for model training.
  • 5.3M users; ARR reportedly grew from $5M to $60M in six months.
  • Team of ~10 people; already profitable per Index Ventures.

The problem they solve

  • Automated benchmarks can't measure design taste; human preference is the bottleneck.
  • Example: a frontier lab tests two image models — Design Arena tells it which one users actually prefer across regions.

Fit

  • Gate 1 — Subjective/taste: The entire product IS taste — collecting and selling human aesthetic judgment. 🔴
  • Gate 2 — Can I start it: Not reached.
  • Gate 3 — Moat: Not reached.
  • Verdict: 🔴 — Fails Gate 1. The product is literally a taste-measurement instrument. Yupp, a near-identical startup, already shut down this year despite raising $33M.

Crowding

  • LM Arena ($150M Series A, text eval); Yupp (dead, $33M raised).
  • Frontier labs may build internal preference pipelines (OpenAI, Google already do).

2. Yuki 🔴 — AI control plane for data cost optimization

Data infrastructure · Tel Aviv / New York · yuki.io · $6M seed (Jan 2026)

What they do

  • Sits above Snowflake / BigQuery / Iceberg and routes queries to cheapest compute.
  • Learns workload behavior; separates critical from low-priority jobs in real time.
  • Claims 42.6% average data-cost savings for customers like Tenable and Angel Studios.
  • Charges a percentage of realized savings — zero if no savings found.

The problem they solve

  • Enterprises overspend on data warehouses by treating all queries the same.
  • Example: a cybersecurity firm's overnight batch jobs run on the same tier as dashboards — Yuki right-sizes each.

Fit

  • Gate 1 — Subjective: Passes. Optimization is measurable, not taste.
  • Gate 2 — Can I start it: 🔴 Product must sit inside the customer's data warehouse. You need access to query logs, warehouse configs, and SLA data. First move is booking a meeting.
  • Gate 3 — Moat: Not reached.
  • Verdict: 🔴 — Fails Gate 2. Can't build or demo anything without sitting inside their Snowflake account.

Crowding

  • Keebo (Snowflake optimization); Select Star; Snowflake's own auto-suspend/scaling.
  • Spot.io (Flexera) founder is an angel — same playbook as cloud cost optimization.

3. Rein Security 🔴 — Runtime AppSec for production apps & AI agents

Cybersecurity · Tel Aviv / New York · reinsec.io · $8M seed (Jan 2026)

What they do

  • Instruments apps in production to see which APIs, libraries, and AI agents are live.
  • Patent-pending runtime context validates which vulnerabilities are actually reachable.
  • Covers API security, SCA reachability, DAST, and AI agent security.
  • Agentless; claims <1ms performance impact.

The problem they solve

  • Static scanners flag thousands of theoretical CVEs; teams waste time on non-reachable ones.
  • Example: a fintech's SCA scanner flags a library — Rein confirms it's not loaded in production, deprioritizes it.

Fit

  • Gate 1 — Subjective: Passes. Runtime reachability is binary, not taste.
  • Gate 2 — Can I start it: 🔴 Must deploy an agent inside a customer's production environment. Cannot build or test without their infra. First step is getting a deployment slot inside their k8s cluster.
  • Gate 3 — Moat: Not reached.
  • Verdict: 🔴 — Fails Gate 2. Product only works deployed inside customer production. No way to start alone.

Crowding

  • Oligo Security (runtime SCA); Kodem; Ox Security ($60M Series B).
  • CrowdStrike, Wiz, and Palo Alto all expanding into runtime AppSec.

4. Flux 🟡 — Code-first engineering intelligence

Developer tools · Boston · askflux.ai · $5M seed (Jun 2026)

What they do

  • Reads git commits directly — no dependency on Jira or manual ticket updates.
  • Classifies every code change: feature, debt, fix, refactor, test.
  • Links code-level activity to quality, security risk, and technical debt metrics.
  • One customer went from 9% to 43% engineering effort on features after using it.

The problem they solve

  • AI-generated code is growing fast (41% of all new code in 2026) and introduces 1.7× more issues.
  • Eng leaders can't tell how much time goes to debt vs. features from Jira alone.
  • Example: VP of Eng sees 70% of commits are churn — Flux traces it to one AI-generated module with ballooning complexity.

Fit

  • Gate 1 — Subjective: Passes. Code classification is structural, not taste.
  • Gate 2 — Can I start it: Passes. Week one: build a GitHub integration that reads commits, diffs, and PR metadata. Open-source repos give unlimited test data. No meetings needed.
  • Gate 3 — Moat: Passes. What accumulates: a labeled corpus of code-change classifications across hundreds of repos. Over time, the classifier gets better at distinguishing debt from feature work. That training set is the moat.
  • Verdict: 🟡 — Passes all three. The thing that erodes it: GitHub Copilot or GitLab add a native "code health" dashboard. Platform risk.

Crowding

  • CodeScene (code health, behavioral analysis); LinearB (dev metrics); Sleuth.
  • Entire ($60M seed, ex-GitHub CEO) working on adjacent AI-code management problem.

  • Gate 3 — Moat: Not reached.
  • Verdict: 🔴 — Fails Gate 2. Must sit inside the customer's agentic infra to function.

Crowding
